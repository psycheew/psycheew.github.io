프로젝트 작업을 하다 보면 아직 파일은 없지만 폴더 구조를 유지하기 위해 빈 디렉토리를 커밋해야 하는 경우가 있습니다.


하지만 빈 폴더를 생성하고 커밋하려고 해도 Git에서는 해당 폴더가 추적되지 않습니다.


왜 그럴까요?


<br>


## ❓ Git은 왜 빈 폴더를 추적하지 않을까?


Git은 **디렉토리 자체가 아니라 파일을 추적**합니다.


따라서 디렉토리 안에 아무런 파일도 없다면 Git이 추적할 대상 역시 존재하지 않습니다.


처음에는 이를 해결하기 위해 내용이 없는 임의의 파일을 추가했지만, 빈 디렉토리 구조를 유지하기 위해 관례적으로 `.gitkeep`이라는 파일을 사용한다는 것을 알게 되었습니다.


<br>


## 🔍 `.gitkeep` vs. 임의의 빈 파일


| 항목 | `.gitkeep`                          | 빈 파일 (ex. `base.css`) |
| -- | ----------------------------------- | --------------------- |
| 목적 | 빈 디렉토리 구조 유지                        | 실제 기능을 담당할 파일         |
| 의미 | 현재 폴더에 추적할 파일이 없음을 나타내는 placeholder | 추후 실제 코드가 작성될 파일      |
| 사용 | 빈 디렉토리를 Git 저장소에 포함하기 위해 사용         | 기능 구현을 위해 생성          |
| 관리 | 실제 파일이 추가되면 삭제 가능                   | 실제 코드가 추가되며 계속 유지     |


<br>


## 💡 왜 `.gitkeep`을 사용할까?


### **1. 의도를 명확하게 전달할 수 있습니다.**


단순히 내용이 없는 `base.css` 등의 파일을 만들어 두는 것보다 `.gitkeep`을 사용하면 해당 파일이 기능 구현을 위한 것이 아니라 **빈 디렉토리 구조를 Git에 포함하기 위한 파일**이라는 의도를 쉽게 파악할 수 있습니다.


<br>


### **2. 실제 파일이 추가되면 삭제할 수 있습니다.**


해당 디렉토리에 Git이 추적할 실제 파일이 추가되면 더 이상 `.gitkeep`이 필요하지 않으므로 삭제할 수 있습니다.


<br>


### **3. 널리 사용되는 관례입니다.**


`.gitkeep`은 Git에서 공식적으로 제공하는 기능이나 특별한 의미를 가진 파일은 아닙니다.


Git 입장에서는 `.gitkeep` 역시 다른 파일과 동일한 일반 파일입니다. 다만 빈 디렉토리를 저장소에 포함하기 위한 **비공식적인 관례(convention)**로 널리 사용됩니다.


<br>


### **4. 특정 언어나 프레임워크에 종속되지 않습니다.**


Git을 사용하는 프로젝트라면 언어나 프레임워크와 관계없이 동일한 방식으로 활용할 수 있습니다.


<br>


## 🌱 정리


Git은 빈 디렉토리 자체를 추적하지 않습니다.


따라서 빈 디렉토리의 구조를 저장소에 유지하고 싶다면 해당 디렉토리에 `.gitkeep` 파일을 추가할 수 있습니다.


```plaintext
empty-directory/
└── .gitkeep
```


단, `.gitkeep`은 Git의 공식 기능이 아니라 **빈 디렉토리를 추적하기 위해 사용하는 관례적인 파일명**이라는 점을 기억해 두면 좋습니다.
